# Working in Cairn

- Deliver repository changes through a pull request against `main`. Create a descriptive feature branch, commit and push the changes, open a ready-for-review PR, and include its URL in the final response. Do not leave completed work only in the local workspace or push source changes directly to `main`.
- Use a specific, user-facing PR title: GitHub automatically turns merged PR titles into changelog entries in Releases. Describe the user-visible behavior and relevant validation in the PR. Run `bash gradlew assembleDebug testDebugUnitTest lintDebug --console=plain --max-workers=2`, `python3 -m unittest discover -s scripts -p 'test_*.py'`, `node --test scripts/test-*.cjs`, and `actionlint` when changing workflows. PR CI also runs pinned actionlint and bounded Node test suites.
- GitHub's **native auto-merge** is opt-in for each pull request, and the `checks` job from **Android checks** is a required strict status check in the `main` ruleset. The repository and `main` ruleset must permit **merge commits only** (disable squash and rebase), because release validation reuse requires a two-parent merge commit. The repository has one maintainer, @dayblox: require **zero** PR approvals, and **do not** require code-owner approval or last-push approval, since a PR author cannot self-approve. For sensitive changes affecting `.github`, release automation, signing or build infrastructure, inspect the whole PR diff before enabling auto-merge; if explicit owner review is desired, leave auto-merge off and merge normally after checks pass. For routine PRs, open a ready-for-review PR and enable native auto-merge with `gh pr merge --auto --merge` or GitHub's auto-merge control after checking the repository merge settings. Never bypass failed, pending or stale checks. Draft PRs are intentionally not auto-merged.
- If native auto-merge is unavailable unexpectedly, leave the PR open and report the blocker; do not bypass branch rules. A deliberate manual merge for a sensitive PR is allowed only after all required checks pass. An administrator can verify the repository configuration with `python3 scripts/configure_native_automerge.py --dry-run` and apply it using the same command without `--dry-run`.
- GitHub merges PRs after requirements pass, triggering the existing `push` release workflow. Merge-generated releases can perform full validation when no trusted PR validation run ID was supplied. Release versions and Android version codes advance automatically; never replace a published release or release a source that does not contain the latest published source.
- PR checks must always run the build, tests and lint before recording validation evidence. Release reuse requires verified evidence for the identical merged tree and toolchain; preserve the full-validation fallback for missing/mismatched evidence and CI/script changes. Never bypass APK signing or release verification.
- Keep signing keys and passwords out of Git, logs, PRs and release assets. CI uses GitHub Actions secrets and verifies the key against `release-signing.sha256`. Reuse the existing key; replace it only with explicit user authorization because Android cannot update an app signed by a different key.
- GitHub's **Automatically delete head branches** repository setting cleans up merged feature branches. Preserve branches containing unmerged work.
