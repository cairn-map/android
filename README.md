# Cairn 0.5.0

A native Android trekking app built around offline maps, a minimal map screen, and user-selected GPS intervals. Cairn is a working name. All required tools, map access, routing data and licences are free of charge.

## This build

- Always-dark interface inspired by Morphe: charcoal surfaces, blue accents, flat rounded controls, and dark dialogs/settings. Map tiles keep their original cartographic colors; controls and scale stay dark. Drawers use the full screen width, with source/licence details in their footers. Transient feedback shares one top-centered banner; distinct notices queue and progress updates replace in place. Imported maps keep their own attribution.
- Manual in-app updates directly in **Routes**: check, download, verify and open Android's installer. No update polling, scheduled jobs or automatic downloads; transfers stop when you leave Routes, and updates are blocked while recording a hike.
- Full-screen map, no header or zoom buttons, two floating Map/Routes destinations. Map mode, location, saved maps and GPS settings sit on the right for one-handed use.
- Smooth pinch zoom, cached geographic backdrops, and center-first loading with up to 32 tile requests in flight. Offline downloads continuously refill available transfer slots; the old 350 ms request delay is removed. Server busy responses pause requests together and honor Retry-After. Saved finer tiles are used immediately at startup and stay visible over overview tiles when zoomed out. Tiles start loading during drags, pinch/quick zoom and momentum, while useful in-flight transfers keep running. Obsolete viewport requests are canceled, and offline enlargements are replaced with real detail when online mode is enabled.
- Double-tap zoom animates briefly on release; holding the second tap and dragging zooms at a consistent rate. A quick flick carries farther on release with smooth, speed-sensitive deceleration. Touching the map stops either animation. The map's search icon suggests mountains, towns and addresses as you type using Photon's partial-name and typo-tolerant OpenStreetMap search, with the map center as a soft ranking bias and the device geocoder as a fallback. Relevant natural features, huts, refuges and other hiking destinations rank higher: for example, “Thabor” favors Mont Thabor over urban namesakes. Geographic qualifiers still matter, accents are ignored, and nearby duplicates are merged. All returned matches remain accessible in the scrolling list, including towns, businesses and addresses. Decimal coordinates work directly. Choose a match to center the map. Search remains available during recording and does not enable online maps.
- Plan IGN through the public WMTS service. Online mode automatically keeps viewed tiles permanently in local storage; the camera is remembered across restarts. No provider account or key is needed.
- A shared route and recording library: tap either kind to select, highlight and fit the entire path on the map, or tap an unselected path directly on the map. Selected items offer Save offline corridor, Export GPX and Hide. Selecting a hidden item shows it again. Swipe left or right to delete a route or finished hike; the active recording is protected. Long-press a saved route to rename it. Earlier single-route databases are migrated.
- One **Add files** action detects GPX, OruxMaps source XML, raster MBTiles, or BRouter regional RD5 data. Android Open with/Share is registered for GPX/XML, including multi-file sharing. XML currently recognizes public Plan IGN; other providers are reported as unsupported.
- Route-specific offline map corridors, saved pack completion checks, pause/resume, update checks, and shared-tile-safe removal. Corridor management lives with its route or recording. Every route and recording has a leading corridor button: a checkmark means ready offline; a muted download icon means missing or incomplete. Tapping it opens the detail/width drawer directly, just like the teal corridor action. Each route keeps one corridor, with its finest saved detail retained when upgrading or changing width. The map's layers menu keeps cache and unlinked-map management. There is no Offline tab or duplicate preview/save-current-area button.
- **Embedded BRouter 1.7.9**, walking profile and lookups. Routes calculate automatically as you place or move nodes in **Edit** mode. Confirm **Download & route** when regional data is missing; progress and a pause action stay in the editor. No companion app, external routing server or paid API. Routing data can also be imported as RD5 files. Calculations are bounded and run only after node changes.
- All drawers use the full available width; variable lists use full height and smaller drawers fit their content. GPS settings apply immediately, with marked intervals for taps and precise whole-second selection while dragging.
- GPS recording in a foreground service, local SQLite storage, a 20-second default with adjustable 1–3600-second requests on a logarithmic slider (60 seconds at the midpoint), and off-route alerts from those same fixes. Manual Locate outside a hike shows a usable cached position immediately and always requests a fresh GPS/network position for up to 30 seconds; during recording it only reuses the recording position and never starts additional requests.
- Transient feedback appears at the top center. No accounts, ads, analytics or cloud sync.

## Install and try

Install the latest APK from [Releases](https://github.com/cairn-map/android/releases) on Android 8.0 or newer. The first automatic release after 0.5.0 uses a replacement signing key and needs a one-time uninstall/reinstall, which removes local app data. Later releases reuse that key and update in place. Passing PRs merge automatically; merged source is tested, signed and published by GitHub Actions once the signing secrets are configured. See [release setup](docs/UPDATES.md).

1. Tap the crossed-cloud icon on the right to load Plan IGN. Pan and pinch; viewed tiles are saved as they arrive. Tap the cloud again for offline maps. This keeps only visited tiles/zoom levels, not an entire area at every detail level.
2. Open GPX/XML from an Android file manager and choose Cairn, or share files to it. Routes → Add files is a single fallback picker with multiple selection. Each GPX stays in the library; several can be displayed together. One route is selected for guidance at a time.
3. Tap a route or recording in Routes to select it and fit its entire path with room around the map controls. Tap an unselected path on the map to switch selection, or tap empty map space to deselect it. The selected item is highlighted. Center selected, Save offline corridor, Export GPX, Hide and the route edit toggle appear as teal icons in a horizontal row beside GPS interval; the library keeps only its rows. Selecting a hidden item shows it again. Route selection also enables guidance; selecting a recording keeps the existing guidance route. Swipe a library row left or right to delete it, or long-press a saved route to rename it. Download a corridor before a trek to cover the full path and chosen detail, including space between GPX points. Tap a route's leading corridor button, or its selected corridor action, to open detail and width settings directly. The same drawer includes resume, update and remove controls for its saved corridor.
4. To create a route, tap the pencil beside GPS interval. Tap the map to place nodes, tap near a leg to insert a node, and drag existing nodes to move them. Walking routes recalculate automatically after changes. Tap the active pencil to finish and save. Select a saved route and tap its pencil to edit it in place; its name and original control nodes are preserved. Finished recordings have the same pencil: drag points to correct positions, tap points to delete them, or tap the map to add points, then tap the pencil again to save the same hike. Recording edits preserve existing timestamps, elevations, accuracy and track gaps; added points have no GPS measurements, and the track is not recalculated against trails. Finish an active recording before editing it. The teal actions sit horizontally beside GPS interval, including **Center selected** for fitting the selected route or recording back on screen. If routing data is missing, confirm **Download & route** once; use Wi-Fi for large downloads. The active pencil pauses a pending download and keeps your nodes; finish editing to retry. Downloads can continue while Cairn is hidden, and calculation waits until you return. Saved maps → Clear all routing data removes all downloaded graphs and paused graph downloads; missing data is requested automatically when editing.
5. Tap the floating GPS pill to choose the recording interval and alerts; changes apply immediately. Tap the slider to choose the nearest marked interval (1, 5, 20, 60, 180, 600 or 3600 seconds), or drag to choose any whole second. Start hike requests precise location permission and optionally notifications. Search and the online map toggle remain available during recording. Starting a hike preserves your online/offline map choice; graph/map pack downloads still stop during recording. Automatic offline routing remains available in edit mode with installed graphs and preserves the GPS interval.
6. Lock the screen for a short test walk. Stop with Finish and export the recording from Routes. Check your phone's actual screen-off recording behavior before a longer trek.

Android file managers differ in MIME reporting. Typed GPX/XML content URIs work even with opaque IDs. Generic binary/plain-text files are offered by filename where exposed; use Add files when a provider does not supply a usable type or filename. Source XML configures the supported built-in Plan IGN source without enabling network access. It does not install arbitrary providers or execute comments/headers.

Raster MBTiles accepts PNG/JPEG tiles in TMS or declared XYZ order. Vector MBTiles and Mapsforge `.map` files are not supported. Routing RD5 imports must retain their original region filename, such as `E5_N45.rd5`.

## Updates on your phone

Open **Routes → App updates → Check**. If a newer release is available, tap **Download update**, then **Install downloaded update** and confirm in Android. Android may first ask you to allow Cairn to install apps; return and tap Install again after granting that permission. No GitHub account or token is needed. Checks only happen when requested and downloads are never automatic. See [update behavior and release publishing](docs/UPDATES.md).

## Offline routing and storage

BRouter code/profile data is in the APK; geographic routing graphs are not. Its 5 × 5 degree graph regions can be hundreds of MB, separate from Plan IGN map tiles. Downloads use HTTPS, range/validator resume, partial files, index/version validation and atomic installation. A region is only published after the transfer completes and validates. Block checksums are checked by BRouter when read. To refresh routing graphs, clear all routing data from Saved maps and let route editing request the missing data again.

**Saved maps → Default routing preferences** sets defaults for future routes. Each routed route keeps its own settings across saves and edits. The editor's **Routing preferences** changes only that route and recalculates it; **Use current defaults** explicitly applies your latest defaults.

Routing uses OpenStreetMap-derived connectivity with the upstream hiking-mountain profile. It can differ from the paths drawn by Plan IGN. See [routing implementation](docs/ROUTING.md) and [third-party notices](THIRD-PARTY-NOTICES.md).

Visited map tiles stay on disk until explicitly removed through the layers menu. Clearing the viewed-map cache preserves downloaded corridors. A downloaded corridor is capped at 20,000 tiles, with a slider covering Plan IGN zoom levels 10–19 and an estimated size before download. The slider, accessibility description and estimate use words from Regional overview to Maximum detail; the default is Junction detail (zoom 17). A second slider selects 0.1–10 km on each side in 0.1 km steps. Packs use the route or recording name automatically. Corridors follow the selected route and width; only tiles touching the buffered route are selected at the chosen detail. New downloads start with detailed tiles, followed by lower zoom levels down to 10 for context. At latitude 45°, an individual zoom-10 overview tile spans about 28 km. Those squares are overview coverage, not the width of the detailed corridor. Saved dates are tile-check dates, not field-survey dates. Complete corridors can be refreshed from their route's offline corridor menu; other packs' shared tiles and unrelated viewed tiles are retained when a pack is removed.

## Battery behavior and limits

**GPS → Phone direction cone** is optional and off by default. Enable it to show where the top of
the phone faces, including in airplane mode. It uses a non-wake-up geomagnetic rotation sensor,
or low-rate accelerometer/compass readings if that sensor is unavailable, without using a gyroscope.
Readings run only while the map and position marker are visible, stop on pause/screen off or opening
drawers, and never change GPS requests or the recording interval. Heading changes are limited to four
updates per second with small compass jitter ignored. Active sensors still use some power; leaving
the option off preserves the previous behavior. Phones without suitable sensors keep the position dot.

Edit mode has no permanent instruction banner; the scale stays in the bottom-left corner. Routing,
download and save progress use the shared top banner only while work is in progress.

During a hike, the map follows each scheduled GPS fix while preserving your zoom. Touching the map or its controls pauses following; after 30 seconds without interaction it recenters on the latest fix and resumes following. It waits while your finger is down, a drawer has focus, or Cairn is in the background. Tap **Find my location** to resume immediately. Following uses the recording's existing fixes and never requests extra locations.

Outside a recording, Locate immediately displays any usable cached position and always requests a fresh position, even if that cache is recent and accurate. This explicitly requested foreground operation is bounded to 30 seconds and canceled on pause or hike start. During recording, Locate reuses the existing position even if old; it does not request faster GPS or network updates. Route/alert-setting changes preserve the GPS subscription when its interval is unchanged. Stopping recording removes subscriptions, including queued configuration cleanup.

The app holds no continuous wake lock, screen-on request, map animation loop or compass polling loop. Search and online maps are user-controlled during a hike. Offline maps make no tile requests; search only runs when used. Online map requests and search stop when the app is hidden. Bulk map and graph downloads remain blocked during recording. Android and GNSS hardware still control actual delivery and receiver duty cycling. **No measured claim of best endurance or superiority to OruxMaps has been established.** Performance checks run entirely in Actions using virtual Android workloads and native Canvas CPU benchmarks; no physical-phone trials are required. See [virtual performance validation](docs/BATTERY-VALIDATION.md).

Hidden recording persists every accepted fix without sending unused UI broadcasts; notification timestamps refresh on received fixes at most every five minutes while hidden. Route guidance skips provably distant route blocks, and map checks reuse projected paths instead of repeatedly projecting the accumulated track. The GPS drawer explains 20–30-second trekking, 5–10-second switchback and 60-second sparse-recording choices. The default remains 20 seconds. See the [multi-day efficiency audit and reproducible interval study](docs/MULTIDAY-GPS.md).

Offline transfers sleep while waiting for completions, server retry deadlines or transfer capacity; cancellation wakes them immediately. Map redraws reuse viewport metadata and attribution, download progress preserves useful pending reads, and the library shares the live recording geometry. Route guidance copies and tile refreshes avoid redundant point binding and PNG reads. See the [app efficiency audit](docs/OPTIMIZATION-AUDIT.md).

If Android kills the recording process, committed points remain but recording does not automatically resume. Reopen Cairn, inspect/export the previous hike, and explicitly start a new recording. Turn alerts are not implemented; off-route alerts use existing fixes and can be delayed by long intervals.

## Build and validation

Use JDK 17, Android SDK Platform 35 extension 15, and Build Tools 35.0.0. Gradle 8.11.1 and Android Gradle Plugin 8.9.2 are pinned by the wrapper/build files.

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

The app uses Android platform APIs and the vendored MIT BRouter Java modules. Test-only dependencies include JUnit, XML Pull/KXml and Robolectric. No paid IDE or runtime service is needed. Build output: `app/build/outputs/apk/debug/app-debug.apk`.

See [validation](docs/VALIDATION.md) for executed checks and the automated virtual performance protocol. Test regional graphs and their original PBF are in `app/src/test/resources/routing`; they are not bundled in the APK. Native rendering previews are generated under `app/build/test-previews/`.
